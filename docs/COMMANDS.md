# Useful commands: Desk

Every command a person or an agent runs day to day, with what it does and when. Keep it current: a command that no longer exists is a defect. Type `drew` on Windows (`desk` is the same program elsewhere). The daily loop for the owner (decide, undo, capture, the brief, lanes and the keys) is on one page: [DAILY-LOOP.md](DAILY-LOOP.md).

## Daily
| Command | What it does | When |
| --- | --- | --- |
| `drew-ui` | starts the web UI on http://127.0.0.1:8765 (`DESK_UI_PORT` to change, `DESK_HOME` for the store). Ctrl+C stops it within two seconds and it prints `Desk stopped.`, also in the window `drew refresh` opens and with a browser tab open: it turns Ctrl+C back on at start (a window opened from a detached script or an agent's shell inherits "ignore Ctrl+C"), event streams end at shutdown, connections are cut after 1 second, and a request still stuck ends with the process 1.8 seconds after the first Ctrl+C (DESK-0308) | every session |
| `drew stop [--port N]` | ends whatever listens on the UI port (default 8765 or `DESK_UI_PORT`) by PID and prints `PID n stopped`; exit 0 and "nothing listens" when nothing does; it does not look at the process name, so it stops any program on that port | before a refresh, or when `Ctrl+C` is not at hand |
| `drew refresh [--ref REF] [--repo PATH]` | one command for stop, install, start: stops the UI as `drew stop` does, runs `uv tool install --force` on the repo (or on `git+file:///<repo>@REF` for a branch, tag or commit; an unknown ref is refused before anything is stopped), starts `drew-ui` again and prints `drew --version`. On Windows, from uv's tools folder, drew.exe cannot replace itself, so a detached `desk-refresh.cmd` does the install after the command exits, opens drew-ui in its own window and writes `desk-refresh.log` (temp folder) ending with the version | after merging or checking out new Desk code |
| `uv run --no-sync pytest -q` | runs the whole test suite | before every report |
| `drew validate` | schema, lifecycle rules, dependencies, track values; a blank assignee on an open ticket is a warning `no assignee (James has not scanned this)` until `[rules] assignee_required_from` in `desk.toml` (default 2026-11-22), an error from that date; exit 1 on errors. It also warns on a ready, claimed or in-progress ticket with `ui` in its `dod` and no ticket assigned to chaz among its `depends_on` or `related` (user-facing work is designed by Chaz first; bug tickets, Chaz's own tickets and a Context line `design: none - <reason>` are exempt), on undispatched work (see `drew dispatch`), on a ready ticket whose `## Commands` is empty or still the placeholder, on a ticket with `ui` in its `dod` that is in review with no screenshot in Attachments, on a ticket tagged `ui` or `ux` (or a `feature` in a project whose profile says `ui: true`) that is in review with no image in Attachments (DESK-0291), and on text that is hard to read (DESK-0253, standards rule 15, "Human-readable by default"): the Context, Outcome or How to validate of an open ticket above Flesch-Kincaid grade 10, or using bone, lane, slice, DoD, fixture, ADR, flush, fetched or "in your mouth" with no gloss beside it (a warning, never an error; code spans, quotes and ids are not read), and on text that breaks the formatting ladder (standards rule 15): a Context, Outcome or Report over 1,200 characters in one block (`readability`), or over 4,000 characters (save it as a Markdown file and link it). DESK-0287: on an open ticket, a Report over 1,200 characters that does not open with a summary (a paragraph of up to three lines and about 400 characters, or up to three findings; a heading, a bold lead alone, a line ending in `:` or a word or two above it is a label, not a summary) warns `<ID>: Report is N characters with no summary on top; open it with up to three lines (or three findings) and the one ask, then the detail (rule 15)`. DESK-0209 (no plain blocks, James 2026-11-09): one warning per free-text section (Context, Outcome, Prompt, Out of scope, Report, Evidence) that holds a wall of text, `<ID>: <Section> has a wall of text (N characters); use a bold lead and bullets (rule 15)`: a prose paragraph over 300 characters, or three or more sentences over 200 without a bold lead, or a list item over 400; blockquotes, code, tables and headings never count, and the ticket page shows the same flag in plain words beside the section's heading. DESK-0215 (GPS, James 2026-11-09): one warning per ticket past triage (ready onward; inbox, triage, done and rejected are not scored) that fails Goal, Proof or Steps, `<ID>: GPS fails G, P and S: <why>`. G: the Outcome opens with one sentence (after an optional `**Goal.**` marker or bold lead) of at most 30 words; P: an Acceptance checkbox line and a How to validate line that names something observable (run, open, prints, shows, lists, returns, see); S: the Prompt has steps and none hides behind a handwaving word (handle, deal with, clean up, improve, optimize, figure out, as needed, as appropriate, etc., and so on, various, relevant, somehow, make sure it works, TBD). A project profile's `gps:` block changes the defaults for its tickets: `goal_max_words`, `proof_requires` (`observable`, `command` = a backticked span in How to validate, `screenshot` = the word or an image file in How to validate, Evidence or Attachments, any other word = it must appear in the Proof), `extra_handwaving`, `allow`. DESK-0208: `parent:` is an error when it names a ticket that does not exist, the ticket itself, or a chain that loops back; a warning when the main ticket is itself part of another (one level is enough) and when a main ticket is done or approved while one of its subtickets is open | before every commit |
| `drew search "words and filters" [--limit N] [--json]` | finds tickets by part of an id, a title, or any word in the ticket's sections and comments, and with `--json` also the Markdown files under `docs/` and `intake/` that hold the words (`files`: path, title, snippet; DESK-0290). A snippet marks the match with the control characters U+0002 and U+0003 in `--json` and `/search.json` (the terminal shows `[match]`, the pages a highlight), so Markdown brackets in the text are never taken for a match. The index is SQLite FTS5 with the trigram tokenizer in `.desk/search.sqlite`, rebuilt incrementally from the files (plain LIKE tables when the SQLite has no FTS5); a save in the UI refreshes that ticket's rows at once: `DESK-00`, `0038` and `chedul` match inside ids and words, a misspelling such as `shceduler` finds the closest spelled words in titles. Filters, mixed with words in any order: `project:` `status:` `type:` `tag:` `ask:` (approve, choose, answer, provide, review) `owner:` `assignee:` `track:` `sprint:` `priority:` `is:stale` `is:open` `is:closed` `before:DATE` `after:DATE` (both on the `updated` date); `a,b` means either, a leading `-` leaves one out, quotes hold a name with spaces (`track:"first real use"`). Results are grouped by project with counts, open before closed, then p0 to p3, exact id first. `parent:DESK-0183` lists that main ticket's subtickets, and a subticket's hit says `part of <ID>: <title>` (DESK-0208) | finding a ticket without remembering where it is |
| `drew outbox --for <actor> [--since last-entry\|DATE\|"DATE HH:MM"] [--json] [--posted]` / `drew outbox --all` | the entry for one coworker thread's team folder (rule 25 header: Date, From: Patch, To, Expires a week out, Supersedes, `Tickets:` listing every id), then one line per ticket: `id · title · status · change · ask: <kind> by <date>`. A ticket is listed when it was assigned or reassigned to the actor since the cut-off, when Patch or James commented on or decided a ticket the actor touched (assigned to them, owned by them, or commented on by them), when it changed after the actor last acted on it, or when it is new and names the actor in Context or Prompt. The ask is `do`, `review` or a decision's approve, choose, answer, provide, with the review-by date, when the ticket is assigned to the actor and open. The cut-off per actor is kept in `.desk/state` (`outbox`); printing does not move it, `--posted` moves it to now (use it when the entry is posted) so the next entry starts where this one ended; with no earlier entry it looks a week back. `--all` prints one entry for every coworker in `people.yaml` that has changes; `--json` is for the poster (actor, cut-off, tickets with changes, text) | after a sweep, to tell each thread what to look at |
| `drew sprint new NAME [--start DATE] [--end DATE] [--owner WHO] [--project KEY] [--note TEXT]` / `drew sprint list` / `drew sprint show NAME` | sprints in `sprints.yaml`: parallel, named like `sprint 6 2026`, across projects and tracks. A sprint is identified by its name and its project (no `--project` means it spans projects), so the same name can exist in two projects. `list` shows each sprint with its tickets and open count; `show` prints its tickets in score order (p0 first, then the sooner review-by) and the burn-down numbers (done, remaining, days left, ideal remaining today, a remaining/ideal figure per day). A ticket joins with `drew move <ID> --sprint NAME` (it must exist; `--sprint ''` takes it out; `--to` may be given too), which sets the `sprint:` field. `drew validate` warns when a ticket names a sprint that is not in `sprints.yaml`; `drew list --sprint NAME` filters; the Previous and Next walk "Within this sprint" uses the field | planning a sprint |
| `drew history <ID> [--by DIM] [--filter KEY=VALUE ...] [--json]` | DESK-0171: the ticket's timeline from its activity log (`events/<ID>.jsonl`, DESK-0162): `Latest change: <who> (<kind>) · <what> · <when>` (the newest change that is not a git save, with `(+N git saves since)` when saves came after it; a git save only when there is nothing else), then every event newest first, one line each: when, who and their kind (Owner, Main session, Coworker, Code session, Subagent, Person), where from (on the page, command line, from old comments, from git history), what (a field old -> new, a section, a comment's first line, created). Besides the log it reads the ticket file's own git history (one `git log` of `tickets/<ID>-*.md` and one `git cat-file --batch`, cached until the file or HEAD changes; nothing is run outside a git repository): every commit the log lacks is listed as a git save, and every commit whose file says a different status from the commit before is listed as a status change from git history (DESK-0305 review), and a ticket with no recorded creation gets a Created line from its created date (from the ticket file). Nothing is written to the log by reading. `--by` actor, kind, source, project, company, track, sprint or field groups the events under that value with counts (a coloured dot per group in a terminal); `--filter` keeps only matching events (repeat it for AND; `a,b` means either; the key or the label works: `kind=coworker`, `actor=james`); project, company, track and sprint are the ticket's values when the event happened. An empty log says to run `drew migrate events --apply` | what happened to a ticket, and who did it |
| `drew undo <ID> [--seq N] [--force] [--dry-run]` / `drew undo --batch <B> [--force] [--dry-run]` | DESK-0284: takes a change back by writing new events (the log only grows). With an id alone it undoes the ticket's last save; `--seq N` undoes one change (its number in `drew history --json`); `--batch` undoes every change of one action across tickets, newest first, or nothing. A field comes back to its old value, a section to its old text (kept in `.desk/undo/`, local), a comment is withdrawn by a new dated line that names it, a Decision by a new Decision line that names the old one, a created ticket is set aside as rejected, and a removed screenshot comes back with its file (kept in `.desk/undo/assets/`). A Decision is undone together with the status it set. Undoing an undo is a redo: a withdrawn comment comes back by a `Restored:` line and a reverted Decision by a `Restores the decision:` line, each naming the original. Without the local undo record (another clone) an id alone undoes only the last change. A change that was changed since is refused with who changed it and when; `--force` undoes it anyway. Each undo event's what-line ends `· undoes #N`, and the undo prints its own batch id, so `drew undo --batch <it>` is the redo. `--dry-run` lists what would be undone, with the count, and writes nothing; it checks the store's rules too, so it refuses what the real run would refuse. No `--as` (decision 110) | you changed your mind, or an agent's change was wrong |
| `drew whoami [--as WHO] [--json]` | how this command line would be recorded on a write: actor, kind (person, thread, session, subagent), instance, source (cli) and how it was established. Order: `DESK_SUBAGENT_ID` (a subagent is `subagent:<id>` with its parent from `DESK_PARENT_SESSION`, never Patch or James), then a name given (`--as`, or `DESK_ACTOR` with optional `DESK_ACTOR_KIND`), then a Claude Code shell (`CLAUDECODE`, the session id from `DESK_INSTANCE` or `CLAUDE_CODE_SESSION_ID`), then the operating-system user and then git `user.name`, each matched to a person in `people.yaml` (`os_users:`). Only the last two are **confirmed**; a name that is only typed is **claimed** and says so. Every write appends a line to `.desk/writes.jsonl` (ticket, actor, kind, instance, source, how, confirmed, as, parent), and every comment carries a hidden `<!-- by ... -->` tag that `drew comments` prints as `[person · cli · os-user · confirmed]` (`not recorded` for older lines; `--json` has an `identity` object) and the ticket page shows beside the author | telling two sessions apart |
| `drew refine <ID> "line" [--review-by DATE --reason TEXT] [--as WHO]` | a tracked refinement of the requirements: adds `- [ ] <date> refinement: <line>` to Acceptance and a dated note to Comments. A refinement may cost time, so `--review-by` moves the date, but only with `--reason`, and the slip (old date, new date, why) is written to Comments. Scope never changes this way: that is `split`. Not for closed tickets | when a requirement gets clearer |
| `drew split <ID> --title "..." [--size xs\|s\|m] [--due DATE] [--details "..."] [--outcome "..."] [--acceptance "..."]... [--as WHO]` | a change of scope does not edit the ticket; it becomes a new ticket (same project, type, priority, dod, tags, assignee; `split_from: <ID>`; review-by = `--due`) that `depends_on` the old one, while the old one lists it under `blocks`, gets a note in Comments, and a prompt in Decision asking for the completion decision: done as scoped, or closed in favour of the new ticket (`drew reject`). The ticket page has the same two actions under Acceptance (Refine or split); a ticket that is thrown (ready or later) refuses a rewritten Outcome with a pointer to Split. The weekly review ticket's Report lists the splits made that week | when the scope changes |
| `drew merge <survivor> <source>... --kind duplicate\|linked\|family --reason "<why>" --signed "<comment link or decision number>" [--with-subtickets] [--dry-run]` | DESK-0263: folds the sources into the survivor and loses nothing. The survivor gains a `## Merged tickets` section (before `## Report`) with, per source, a header line (id, title, project, status at merge time) and the source file's full text in a fenced block, indented four spaces so the `## ` lines inside it are never read as the survivor's own sections (`desk.merge.embedded()` gives the exact text back); every open `- [ ]` Acceptance line of a source is added to the survivor's Acceptance as `- [ ] (from <ID>) text`; the source's project joins the survivor's `also_projects:` (only projects other than its own). Each source becomes `rejected` with `merged_into: <survivor>` (kinds linked and family) or `duplicate_of: <survivor>` (kind duplicate), `updated:` today and a Decision line `rejected · "merged into <survivor> (kind <kind>): <reason>. Signed: <signed>."` written under the name of whoever really runs the command (there is no `--as`); the source file stays. Any other ticket whose `depends_on`, `blocks` or `related` names a source is repointed to the survivor with no duplicates, and so is the `parent:` of each source's subtickets; each repoint is printed (a survivor that listed a source simply drops it). A source with an open subticket is refused, naming each one, unless `--with-subtickets` is given. The survivor gains each source's own `depends_on` (no duplicates, never a source or itself; each addition printed), so `drew done` still waits for the work a source waited on, and takes the highest priority of survivor and sources (printed). A survivor in `review` gets a Comments line saying the carried `(from <ID>)` lines arrived during review and are unchecked. Refused with a plain message and exit 1, writing nothing: a survivor that is done or rejected, a source that is `in_progress` or `claimed`, a source that is done or already merged, a source equal to the survivor, a survivor that is a subticket of a source, an unknown id, a missing `--reason` or `--signed`. `--dry-run` prints the plan and writes nothing. Only the lines named above change (the files are edited as text, not re-rendered), and a merge that would leave a ticket with a new validation error writes nothing. A project's board, `drew list --project` and the Scores page list a ticket whose `also_projects` names that project; a merged-away ticket's page opens with a "Merged into <survivor>" banner. `drew validate` errors on an `also_projects` entry that is not a project. Not done: the search `project:` filter still matches the ticket's own project only | merging duplicates or linked work, instead of closing one and losing its acceptance lines |
| `drew repeats [--apply]` | the repeated-ask detector (rule: repetition is an emergency). A repeated ask: the store owner commented twice on one ticket within 7 days asking for the same outcome (normalized text: lower case, no punctuation or filler words, at least three content words each, 60% shared); writing the second comment already makes the ticket p0 with the tag `emergency`, `drew validate` warns `repeated ask` while the pair stands, and `--apply` escalates any that were written before this existed. A stale hand-off: `blocked_on` names the owner and the ticket file has not changed since before the second-to-last sweep (sweep times are kept in `.desk/state` by `drew comments --mark-sweep`): `waiting on James since <time>; is the hand-off real?`. `drew comments --mark-sweep` prints these as `FLAG ...` lines before anything else | the sweep |
| `drew dispatch [--json]` | the tickets nobody has started: status `ready`, assigned to Patch, every dependency in review, approved or done, `blocked_on` empty, and the file unchanged for more than an hour; grouped by repository (the project profile's `repo:` line, else the project key), the repo with the longest wait first, oldest ticket first, each with id, size, effort, waiting hours and dependencies. `drew validate` warns on the same tickets (`undispatched for N h`); setting `blocked_on` to the worker's name or a reason silences it. The wait is read from the ticket file's modification time, since `updated` holds only a date | at the start of a sweep, and whenever a delivery makes tickets ready |
| `drew assign-rules` / `drew assign-rules init [--force]` | shows the auto-assignment rules (`assign.yaml` in the store, else the built-in table: decisions and human review to james, design review and brand to chaz, security to bigd, research to em, tech and product to lily, calendar, orders and admin to bri, legal, finance and channel to joe, a project session keeps `code:<project>`, build work falls back to main); `init` writes `assign.yaml` to edit. `drew new` and `drew intake` fill a blank assignee when the rules name exactly one person (two different people leave it blank and print a warning); a rule never changes an assignee someone set; the ticket page says "assigned by rule <name>" until a person changes it | setting up, or changing a mapping |
| `drew people` / `drew people init [--force]` | lists the people an owner or assignee can be, in the groups of the dropdown (People, Code sessions, People outside the team), with kind, colour and role. They come from `people.yaml` in the store, or the built-in team (james, main shown as Patch, chaz, em, bri, joe, lily, bigd, and the `code:<project>` sessions) when there is none; `init` writes that team to `people.yaml` to edit. If `~/.claude/jeby-private/people.yaml` exists (or the file named by `DESK_PRIVATE_PEOPLE`) its people are added, kind `external` unless it says otherwise; it is read, never copied into the store, and a ticket holds only the key | setting up, or adding a person |
| `drew list [--project] [--status] [--assignee NAME] [--all]` | table of open tickets, with an assignee column; a subticket's title ends with `(part of <ID>: <title>)` (DESK-0208), so `drew list --assignee chaz` shows Chaz's pieces of bigger tickets | start of a session |
| `drew list --sort score` | the same table ordered by the priority score, highest first (DESK-0135; docs/PRIORITY.md). Every `drew list` carries a `score` column (blank on a closed ticket); hand-set priority is one input to the score, not the order | to see what Desk would do next, across projects |
| `drew explain <ID>` | why a ticket scores what it does (DESK-0137): the score and its band, the top three reasons in plain words, then every term with its points and which level set its weight (default, store `[priority]`, track rules `weights:`, project `priority:` block, private file). The private people file is reported as present or absent, never printed | when a ticket sits higher or lower than expected |
| `drew list --due DAYS` | the open tickets with a hard deadline within DAYS days or already missed, soonest first, each with the date and days left in words (`due in 3 days`, `missed by 2 days`): the same set as the Immediate Action Required row on Today (`drew list --due 14`). Soft and sprint deadlines, closed and approved tickets are left out | to see what cannot slip, from the terminal |
| `drew deadline <ID> <YYYY-MM-DD> --hard \| --soft \| --sprint [--as WHO]` / `drew deadline <ID> --clear` | sets `deadline:` and `deadline_kind:` on the ticket and writes a dated line to Comments. `review_by` stays the soft date to look again; only a hard deadline reaches Today's Immediate Action Required row (top of Today: hard deadlines in the next 14 days or missed, soonest first, five then "N more", red when one is missed). `drew validate` checks that the date is a date, the kind is one of hard, soft, sprint, and that one never appears without the other. `drew new ... --deadline DATE [--deadline-kind hard\|soft\|sprint]` sets it at creation (kind defaults to hard) | when a real date appears |
| `drew assign <ID> --to NAME [--note "..."] [--handoff URL_OR_DOC_ID] [--as WHO]` | sets `assignee` (a display name such as `Patch` or `Big D` is stored as its key, `main` or `bigd`; see `drew people`), `assigned_at` and `assigned_by`, optional `handoff`, appends `- <date> · <actor> · assigned to <name>: <note>` to Comments. Done means: assignee named and notified; the hand-off record linked | handing a ticket to someone |
| `drew comment ID "text" [--kind Question\|Suggestion\|Concern\|FYI] [--as name]` | adds a dated, timed comment that always has a kind (Question unless you say otherwise), kept at the end of the line as `<!-- kind: Concern -->`; the same words from the same author within 10 minutes, whatever the kind, are refused as a duplicate | any time; the same person posting the same words again is ignored: within 10 minutes when identical, within 60 seconds when only case, spacing, punctuation, brackets, a trailing number or a typo or two differ (`Dup test # 2 ()` is `Dup test # 2`), and `james`, `james1` and `james_` count as one person; the earlier comment is named and the UI highlights it |
| `drew comments [--author NAME] [--since DATE\|"DATE HH:MM"\|last-sweep] [--unanswered] [--answered-by NAME] [--json] [--mark-sweep]` | lists every word people wrote in Desk across the store (ticket, time, author, kind, text; `--json` gives a list with ticket, title, when, author, kind, text, answered, identity, source). DESK-0322: not only Comments lines but also the **Not accepted** reasons (the reason with the acceptance line it is about, by whoever pressed the box), **Decision** lines (Approve, Send back, Decide mode, Move to approved or rejected; a Decision line has a day and no time, so it is shown by day and `--since` keeps it for that whole day), **Park reasons** older than DESK-0324 (read from the activity log), and a yes/no answer a session recorded as `Decided by <name> (...)` (listed under that person with the kind `Answer (relayed by <writer>)`, never as if they typed it). `source` in `--json` names where the words live: comment, decision, not accepted, park reason or relayed answer. A comment is timed to the minute and a sweep mark to the second, so a line from the mark's own minute is listed again rather than lost. `--unanswered` keeps comments with no later line by patch in the same ticket and no change to the ticket on a day after its last comment (dates are days, so a same-day change leaves it open). `--since last-sweep` reads `.desk/state` (everything when none is marked); `--mark-sweep` records now as the last sweep after listing, or alone just records it. The Today page shows the owner's open count in an "asked" block and the weekly review ticket's Report carries it | the sweep, first: `drew comments --author james --since last-sweep --unanswered`, answer each, then `drew comments --mark-sweep` |
| `drew lane <ID> now\|planned\|later\|parked [--reason "..."]` / `drew lane <ID>` / `drew lane <ID> --clear` | DESK-0283: puts a ticket in a lane (`lane:` in the front matter) and logs the change in its activity log; with no lane it prints the lane, saying when it is worked out rather than set (p0 or an `emergency` tag is now, inbox and triage are later, the rest planned); `--clear` goes back to that worked-out lane. Parked needs `--reason` | when you sort what to do now from what can wait |
| `drew snooze <ID> <YYYY-MM-DD\|1d\|1w\|2w\|next-monday>` / `drew snooze <ID> --clear` | DESK-0283: writes `snooze_until:`; the ticket stays off Today, Needs me (Today, the board, `drew needs-me`) and the board until that date, then comes back with a **Back from snooze** marker for three days. A snooze ends on the ticket's hard deadline if that comes first, so it never hides one. A date that is not after today is refused. `--clear` brings it back now | an honest "not this week" that is not a decision |
| `drew park <ID> "reason"` | DESK-0283: `lane: parked` plus a one-line `park_reason`; nothing is deleted, and `drew lane <ID> planned` brings it back (the reason leaves the file but stays in the activity log). `drew validate` warns when a Later or Parked ticket has a branch or a worker (claimed or in progress), when an emergency (p0 or tagged `emergency`) is put in Later or Parked or is snoozed, and when a snooze runs past a hard deadline; `drew lane`, `drew snooze` and `drew park` print the same warnings for the ticket they just changed | when an idea is decided "not now" |
| `drew needs-me [--as NAME] [--json] [--seen ID...] [--seen-all]` | the tickets with an ask for you (a decision ticket you hold, a review only you may approve, a ticket you hold to do) and the tickets someone else changed since you last acted on them (a comment, a checked line, a status, Report or proof change); each with its reason line (`ask: approve · from Patch · due Mon`, `changed: 2 comments by Lily · 5:10 AM`) and a closing `N asks for you · K changed by someone else`. Reading a ticket never counts as acting. `--seen ID` is Mark seen (clears a change without acting; asks stay until answered), `--seen-all` clears every change | start of a session, before the comment sweep |

## Notifications
Phone push and email for the morning brief and alerts; the full guide, costs and your steps are in [NOTIFICATIONS.md](NOTIFICATIONS.md).

| Command | What it does | When |
| --- | --- | --- |
| `drew notify pair [--new]` | makes a random 32-character ntfy topic, saves it in `%USERPROFILE%\.desk\notify.env` (outside every repository; `DESK_NOTIFY_ENV` names another file) and prints the phone steps and the subscribe link; run again to see the same topic, `--new` replaces it | once, to pair the phone |
| `drew notify test [--channel NAME]` | sends one line, "Desk test: notifications work", to every channel that is on, and says which worked; with `--channel NAME` it says why that channel is off when it is | after pairing or changing a key |
| `drew notify brief [--dry-run]` | sends the morning brief (ids, titles that pass the private-term scan, counts) with held items folded in; `--dry-run` prints exactly the text and sends nothing | each morning (scheduled), or to preview |
